ControlEvent v4_1_exp · VOICE-NEXT 1
====================================
Objetivo: reconstruir desde cero la capa oral sin tocar el cerebro VNext/CE ni el resto de módulos.

Arquitectura nueva:
  Micrófono PCM 16 kHz -> Gemini Live (una sesión persistente) -> tool route_voice_turn
  -> VNext/CE existente -> spokenAnswer -> misma sesión Gemini Live -> audio PCM 24 kHz.

Eliminado del runtime de conversación (el cliente v22 anterior no se incluye y sus rutas /zuzu-voice no se montan):
  - Web Speech / SpeechRecognition.
  - speechSynthesis / SpeechSynthesisUtterance.
  - MediaRecorder como transporte conversacional.
  - Auto / Leer / selector de voces / selector de micrófonos.
  - mensajes hablados de entretenimiento.
  - botón VNext y ruta BANK antigua: VNext queda obligatorio.

Interrupción:
  Live usa START_OF_ACTIVITY_INTERRUPTS; al recibir serverContent.interrupted se vacía
  inmediatamente toda la cola de audio del navegador. No hace falta acertar una frase fija:
  empezar a hablar corta a Antonio. Las frases Para/Calla/Perdona Zuzu-Antonio se reconocen
  además como controles para que no se envíen como consulta vacía a CE.

Despertar:
  Mientras está dormido, todo habla se ignora salvo que contenga Zuzu/Antonio (y variantes).
  La decisión se hace en el cliente sobre la transcripción del único canal Live.
  Abrir manualmente la ventana Zuzu también deja la conversación despierta.

Voz:
  Modelo por defecto gemini-2.5-flash-native-audio-preview-12-2025 y voz Algenib.
  Se usa 2.5 Live porque la selección de voz prebuilt es estable; no se mezcla ninguna voz del navegador.

Seguridad:
  La clave Gemini nunca llega al navegador. El servidor crea un token efímero de un solo uso,
  limitado a la configuración y tool de VOICE-NEXT.
